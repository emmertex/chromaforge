- **Plug-in Manager**: **File ▸ Plug-ins ▸ Plug-in Manager…** installs, enables and configures plug-ins. Drop a `.wasm` file on it, or **Install from File…**.
- **Sandbox**: a plug-in runs as WebAssembly and can only do what you grant it.
- **Permissions are asked at run time**: installing grants nothing (the install dialog only lists what a plug-in may ask for). The first command that needs a permission shows a prompt: **Allow** runs the command again, **Deny** is remembered.
- **Nobody to ask**: from the command line, an agent, a background job or a hook, a call that needs a permission is refused and says to allow it in the Plug-in Manager. Only you allow; commands and agents can only take permissions away.
- **Permissions tab**: each request as allowed, denied, not asked yet or refused, with **Allow** and **Revoke** (`plugin.revoke` takes one permission away).
- **Updates keep the previous version**: **Go Back to Version X** on the plug-in's page (`plugin.rollback`) restores it with its settings.
- **Remove** asks first and can keep the plug-in's data and settings.
- **About tab**: description, commands, and where the plug-in comes from: Homepage, Source Code, Changelog and Licence links, plus **Report a Problem** for a GitHub repository. Pixel filters show the same links on their page.
- **What a plug-in can add**: menu commands with dialogs, settings pages, export post-processing, export destinations ("Then send to"), publish services, metadata and keyword suggestions, custom metadata fields, programs it starts, pixel filters.
- **Commands** appear under **File ▸ Plug-ins** and run as `plugin.run`, so CLI, MCP and actions can run them too.
- **SDK**: write plug-ins in Rust with the `sdk/plugin` crate. Eight example plug-ins live in `sdk/examples` (catalog tools, batch metadata, export tools, publish folder, program tools, custom fields, job tools, keyword picker).
- Lightroom Lua plug-ins are not supported.
