# 26.45.0

## Develop and masking

- **Masking panel ergonomics:** add dedicated overlay options menu (`…`) with Image on B&W mode, automatic overlay toggle, and unselected pin visibility; center mask title and enlarged action buttons; remove redundant Edge slider in favor of Refine Edges. Fork #694. (no PR)
- **Cleaner colour at high ISO:** Colour Noise Reduction now detects chroma speckle — the isolated green and magenta single-pixel dots a noisy high-ISO raw shows (most visible in skin tones) — by testing each pixel's chromaticity against the median of its 3 × 3 neighbourhood, and pulls speckle fully in at the slider's existing settings, where the plain blur mix left most of it visible. Ordinary colour texture and straight hue edges pass the median test and keep the gentle mix, so low-ISO photos are unchanged. Both the processor and the graphics-card pipeline. Chromaforge #679. (no PR)

## Develop

- **Lens database matching:** a profile is found even when lensfun's name carries a maker's designation code
  the metadata omits (Tamron "… Macro B016", Sony A-mount), and a compact camera's built-in lens wins over
  another lens that merely shares the EXIF name's numbers.

## Library

- **Capture dates of a year or a month alone:** a photo dated only `1983` or `1983-04` (a scanned print's
  `photoshop:DateCreated`) keeps that date as stated instead of failing a Lightroom catalog import: it shows as "1983" or
  "April 1983", sorts and groups at the start of its period, can be typed in Edit Capture Time, and is written to XMP
  `photoshop:DateCreated` only. A Lightroom capture time that isn't a date imports the photo without it, with a warning.
- **AND / OR in the metadata filters:** the Lens, Keyword and People multi-selects take a Match any (OR) /
  Match all (AND) toggle, in the filter bar's pickers and per Metadata column; AND shows only the photos carrying
  every chosen value together (issue #683). Camera has none: a photo has only one camera. Clearing a filter's values puts it back to OR. (no upstream PR)
- **IPTC Content fields:** headline, description writer, category, other categories and IPTC subject code are now edited in the Info panel's IPTC view, kept in the library, written to XMP sidecars and exported files, and read from files and sidecars other tools wrote. Issue #687. (no PR)
- **Local time for the app's clock:** Today, Yesterday, This Week and In the Last… rules, import and edit stamps, last backup and last sync use this computer's time zone instead of UTC. (no PR)

## Import, export and formats

- **Web gallery upload checks the server first:** Upload Web Gallery logs in before it renders any photos, so a wrong password, an unreachable server or an unconfirmed host key shows up right away. (no PR)

## Import

- **Lightroom catalog edits win over a raw's own XMP:** catalog import gives the photos it adds, and browsed photos
  unchanged since browsing, the catalog's develop settings, history and snapshots, instead of the settings saved in
  the file (embedded in a DNG or in a `.xmp` sidecar), which dropped every edit made in Lightroom since the file was
  last written. Settings the catalog leaves out start from the camera's defaults. (⇠ #3435)

## Performance

- **Faster raw demosaic:** the default AHD demosaic takes its Lab cube roots with two Halley steps instead of the library `cbrt`, the most expensive call in it. (no PR)
- **Delete from Disk lists each folder once:** deleting hundreds of photos from one folder took half an hour or more, the folder being listed and every entry stat-ed again for each photo's sidecar lookup. One deletion now lists each folder once and answers the sidecar and shared-stem questions from that listing. Fork #692. (no PR)
- **No more idle freezes while the catalog is compacted (fork #448):** *Optimize Library* writes its snapshot on a
  worker thread now, like the automatic compaction; on a 28 000-photo library it froze the window for tens of seconds
  at a time. Files that can't be decoded (an unsupported raw compression, a broken JPEG) are negatively cached, so
  visiting their cell no longer decodes them again and again. The log records when a compaction starts and lands, and
  each stage's timings. (no PR)
- **Faster grid with thumbnail badges:** enabling View Options ▸ Show Thumbnail Badges no longer freezes scrolling, selecting and hovering on large libraries — the badges' sidecar naming was worked out per visible photo, per frame (a pass over the whole catalog each time, ~33 ms at 100,000 photos); the owner table is now built once per catalog change and reused (issue #742).

## Fixes

- **Plug-in Manager fixes:** the window opens at its usual width whatever is installed (a pixel filter with many parameters made it nearly as wide as the screen, and it only got wider) and drags narrower as well as wider, with a page's text and the folder line wrapping or shortening to fit. While the install dialog waits, another module is refused with a note to finish the first instead of replacing it. A module that is exactly what is installed selects its entry instead of asking again (`plugin.inspectFile` gives `installed.same`; `plugin.list` gives a plug-in's `moduleHash` and `settingsRevision`). An open Settings tab shows an update's fields and values the plug-in set itself, keeping what was typed and not saved, so *Save* no longer writes old values over newer ones. "Plug-in Manager" is the one spelling in messages and docs.
- Whites, Blacks, Highlights and Shadows follow Lightroom's tonal response much more closely (issue #1371).

## Fixed

- Update checks now recognize release downloads under both the current repository and legacy repositories, fixing update checks when prereleases are enabled.
- The Check for Updates dialog only displays "This is the newest version." when the check confirmed the current version is up to date, avoiding misleading status messages during failed checks.
- Malformed capture times (one-digit UTC offset minutes or ISO clock fields, impossible UTC offsets in date rules, an IPTC Time Created with trailing text) are refused instead of being read as a nearby valid time, so a valid fallback applies.
- Shutter fractions with a zero or negative part, a fractional XMP orientation and a `.cube` file with a non-numeric value are refused instead of being half-read.
- RW2 files read ISO and other missing Exif from their embedded JPEG; D1X files with square resolution tags take their pixel shape from the preview.
- Decomposed Korean and Vietnamese text now draws whole in exports; Settings > Performance no longer waits for the preview cache's size; adding a gradient to a mask disarms an armed brush, object tool or eyedropper.
- Nikon D800E 12-bit NEFs develop at the D800's measured frame, without a magenta bar of filler columns on the right.
- Importing many camera profiles (.dcp) for one camera no longer makes the first one its default, and Settings > Import lets you choose the default camera profile for all cameras or per camera.
- Imported presets, camera profiles (including `.dcp` files) and printer profiles are read only when they are regular files, so naming a pipe or a device reports an error instead of hanging or exhausting memory.
- A slideshow template with linked margins keeps unequal margins across a save and reload.

## Immich

- **XMP sidecars both ways (IMM-SIDECARS):** pull the sidecar Immich stores for a linked asset (`GET /asset-files`,
  v3.2.0+) into the catalog and the local file — metadata plus the `lc:settings` develop settings another instance
  published — and push the catalog's: whole sidecars for external-library folders, and the rating, description,
  capture time, place and tags Immich keeps for managed assets. Photos edited here after the asset changed are
  skipped unless overwritten. For managed assets an opt-in **full** mode reads the sidecar Immich holds, merges the
  catalog's metadata and develop settings into it (other apps' data stays), and copies it back through a tiny
  temporary asset (`PUT /assets/copy`), removing the temporary asset afterwards — the original is never deleted or
  re-uploaded. Publishing an original also carries its whole XMP (docs/immich.md).
- **Publishing an original now carries its XMP sidecar:** the whole XMP (metadata and develop settings) goes with an
  uploaded original, and Immich no longer rejects that upload ("Unsupported file type"): the multipart file parts are
  sent before the text fields, which is what its upload endpoint expects.

## Changed

- Process V6: AI Denoise's Amount eases in (`1 − (1 − a)³`), so 50 leaves about a sixth of the noise instead of half. Photos on older processes render as before.
