# 26.46.1

## Library

- **Face review queue with background scan off:** suggestion previews, the review queue on a person's page, and accept/reject actions remain fully accessible when automatic background face recognition is turned off. You can curate, confirm, or reject face suggestions on existing embeddings without continuous background AI indexing. Issue #887.
- **Aperture and Shutter Speed filters:** the filter bar's Metadata columns can list Aperture and Shutter Speed beside ISO (issue #851).
- **Unnamed and suggested faces follow the sidebar:** in People, the Unnamed faces list and, on a person's page, their faces and the suggested faces are narrowed to the year, folder or album picked in the sidebar. Issue #685.
- **Local folders show library photos:** choosing a folder under Local shows every photo in it again, including those already in the library, instead of keeping the Import tab's Show Not Imported filter (regression in 26.45.3). Issue #881.

## Interface

- **Eight more languages fully translated:** Polish, Czech, Italian, Georgian, Swedish, Finnish, Indonesian and
  Vietnamese now translate Chromaforge's own screens as well as upstream's, and the coverage tests hold them to
  every message, as the other languages.
- **More of the interface translated:** text that skipped the translation catalogs (label colour names, the sample
  copyright and creator, the Layout Image notice, face recognition messages, the web upload server fields and more)
  now shows in the chosen language, and a test checks every source file and the painted screens for text that skips
  them.
- **Nine languages fully translated:** German, Spanish, French, Japanese, Portuguese (Brazil), Russian, Ukrainian
  and Chinese (Simplified and Traditional) now translate every interface message, and a test fails when one of
  them lacks a translation.

## Performance

- **Face recognition GPU acceleration:** face recognition now benchmarks batch throughput rather than single-face dispatch latency when testing GPU support, ensuring dedicated graphics cards remain active during catalog face indexing. Settings ▸ Faces reports accurate status for face detection and recognition.
- **AI semantic search hardware selector:** Settings ▸ Performance and Settings ▸ AI Models now include an explicit device selector for AI natural-language semantic search embeddings, choosing between Automatic, detected physical GPUs, and CPU. Status reporting truthfully reports active hardware with fallback reasons (`whyCpu`) and properly binds device indices on Metal/macOS. Fixes #868. PR #882.

## Fixes

- **Grid:** a photo whose original is missing keeps its last thumbnail after an update that changes how thumbnails are cached, instead of showing an empty cell; thumbnails cached by recent earlier versions are found too. Once the original is back, even while the app is open, its thumbnail is rendered again.
- **GPU colour noise reduction on Windows matches the CPU again:** on photos edited with an older process version (before V8), Color noise reduction on the graphics card picked the wrong 3 × 3 median on Vulkan, which Windows uses by default since issue #934. The result differed from the CPU render by up to 81 8-bit levels in colourful areas. The median now uses a comparator network that gives the same result on every backend.
- **Canon EOS 7D framing:** CR2 files whose camera JPEG shows the whole frame no longer take the maker note's aspect crop (a 7D was cropped to 4:3). Issue #964.
- **Startup error:** the silent check for an older install's presets no longer shows an error when there is none. Issue #965.
- **Unreadable folders:** browsing a folder that can't be listed shows the reason instead of an empty "No photos in this folder". Issue #966.
- **Control-surface layouts carried over:** on start, when Chromaforge's settings folder has no `control-surfaces.json`, it is copied from the first previous name's settings folder that has one, also when the settings folder already existed. An existing file is never overwritten, and a failed copy is logged.

## Plug-ins

- **Safer installs and updates:** an update keeps the version it replaced, and *Go Back to Version X* (`plugin.rollback`) restores it with its settings; Remove asks first and can keep a plug-in's data and settings (`plugin.uninstall {keepData}`); installs name unknown manifest fields; a plug-in and a pixel filter can't share an id, a second module with an id is listed instead of hidden, and modules past the folder's limit are counted; older pixel filters need confirming.
- **Permissions asked for at run time:** nothing is granted at install; the first call that needs a permission asks the user from a command they started, its prepare step included (Allow runs it again, Deny is remembered), and is refused with nobody to ask: from the command line or an agent, in a job and in hooks. Only the user's own input allows: `plugin.install {grant}` and `plugin.grant` can only revoke, the new `plugin.revoke` takes one permission away, and control-channel clicks can't allow. `plugin.list` reports each request's state, and folder roots over the settings or plug-ins folder are refused.
- **Where a plug-in comes from:** manifests may carry `homepage`, `repository`, `changelog` (`https://` links) and `license`, for plug-ins (host feature `about`) and pixel filters. The About tab and a filter's page show them as links named by their host, with *Report a Problem* for a GitHub repository; `plugins.openLink {id, link}` opens one. A value the host can't use is dropped and named in the plug-in's log and the install dialog, never an install error. The SDK's `export_plugin!(package: …)` fills `version`, `description`, `author`, `homepage`, `repository` and `license` from the plug-in crate's `Cargo.toml`. Host feature `pictures` names a plug-in's `icon` and `header`.

## Features

- **Lightroom-matched colour for two more cameras:** the Pentax K-3 and the Sony ILCE-7M5 join the cameras with a built-in calibration fitted to Lightroom's exports.

## Changed

- **Export, full-quality preview:** the Export module's preview of a single photo draws the loupe's own render (with the thumbnail standing in until it arrives), instead of a thumbnail ladder render capped at 512 px scaled up to fill the preview area. Entering the Export or Print module from Develop now selects the photo open on screen (Develop's filmstrip can hold a multi-selection while another photo is stepped to); a selection made outside Develop is kept.
- **Print, the filmstrip selection is what prints:** with one photo selected the Print module's page and its job take that photo (choosing another photo in the filmstrip moves the print to it), instead of falling back to every photo in the filmstrip. Only an empty selection prints the whole filmstrip.
