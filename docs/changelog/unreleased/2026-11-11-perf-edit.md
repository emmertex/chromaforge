## Performance

- **Faster editing on photos with AI masks:** dragging a slider no longer evaluates every mask again — the mask caches compare the photo's mattes by content instead of by pointer, so a drag hits the cache — and the Subject and scene model analyses are keyed by the photo's identity instead of its decoded pixels, so they run once per photo, whatever size it is decoded at, shared between the loupe, a 1:1 window and exports (the Subject model takes 11–23 s on the processor, up to 160 s under load, and one photo ran it three times while being edited). A Source plug-in filter, or a source without identity, keeps the old pixel key. Thanks @OneSlips. PR #1052.
- **No UI stalls while exports or Build Previews run:** the Windows build embeds an application manifest that opts the executable into the Segment Heap (Windows 10 2004 and later; older versions ignore it) — on the default NT heap every large free took one process-wide lock, and while batch work ran, the render workers' image buffers kept it busy: the window's thread waited on it in ~45 % of samples, with frames of 50–300 ms. Thanks @OneSlips. PR #1052.
- **GPU memory is freed after batch work:** the idle trim frees both graphics cards' buffer pools (the second card's kept up to an eighth of its budget for the rest of the session), and the renderer trims again once batch work has finished, if the pools grew since its last trim. Measured after an export of 50 photos and a 1:1 build of 60: 3.8–4.0 GB of buffers still pooled after 30 s idle, now freed. Thanks @OneSlips. PR #1052.
