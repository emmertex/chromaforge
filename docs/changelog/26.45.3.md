# 26.45.3

## Develop and masking

- **Masks stay on the photo, review fixes:** old gradients attach through the warp's local shape, masks brought in by paste, sync, presets or history attach from the settings they came with, kept masks turn with a synced rotation, Object clicks on old masks are read on the photo, and linear-gradient guides follow the warp.
- **Masking tools toggle off:** clicking an active masking tool tile (Brush, Object, Linear Gradient, Radial Gradient) disarms it. Brush and Object selection now offer an inline Done button, and pressing Escape cleanly disarms the active tool without closing the Masking panel.
- **Trackpad scroll resizes brushes:** with the Masking or Remove brush active and "Mouse wheel resizes brush" enabled, two-finger vertical scrolling on a trackpad adjusts the brush size instead of panning; holding the Space bar restores the hand tool to pan the frame around. PR #808.
- **Background AI results merge into your edits:** recomputed AI masks, Retouch parts and Smooth Skin analyses are merged into the settings as they are when they arrive, and into undo / redo, a running drag's start and History, so no edit or result is lost.
- **Describe on open models:** without SAM 3, Describe masks run on the OWLv2 object finder (Apache-2.0, `ai.models.download {"id": "describe"}`) and SAM 2.1: OWLv2 finds the boxes that match the words, and SAM 2.1 segments each one. SAM 3 is still used when it's installed or remote.
- **Every mask kind in Add / Subtract / Intersect:** the menus list every Create New Mask kind with its icon (Background, People, Remembered and Color were missing); People and Remembered picks combine with the selected mask.
- **Mask points as `{x, y}`:** mask commands read a point as `[x, y]` or `{x, y}` (how a point serializes), so a gradient sent by an agent or a script lands where it was drawn instead of at the default place.
- **Masks opens on a mask:** entering Masks selects the only mask, else the one selected last on that photo, else the first; a new-mask tool put away without drawing gives the earlier mask back.
- **Overlays hide while adjusting:** any slider or console dial, not only a mask's own sliders, hides the overlay, pins and tool graphics (mask lines and handles, Remove spots, crop guides, red-eye circles) while it moves; sliders that shape the tool's graphics keep them.

## Develop

- **AI Denoise for finished pictures:** JPEG, PNG, TIFF and other finished pictures can be denoised with a model made for them, chosen separately from the raw model (`denoise.models.select {kind: "rgb"}`); the denoised picture is cached and mixed in by the Amount slider like a raw photo's. Thanks @alexbystrow.
- **AI Super Resolution and AI Sharpen:** Photo ▸ Enhance… runs an installed upscaler (Real-ESRGAN General v3, BSD-3-Clause, opt-in `realesrgan-model` download, or any `rgbToRgb4x` ONNX) on the pure-Rust CPU/GPU runners: 2× or 4× (`enhance.superResolution {method: "ai"}`) or sharpened at the same size (`enhance.aiSharpen`), into a new 16-bit TIFF (sRGB, Display P3 or Adobe RGB, `space`) with the photo's edits baked in, stacked with it. Thanks @cbram.
- **RAF colour look fitted on the vignetting-corrected sensor:** the per-file look fitted to the camera JPEG now sees the sensor with the embedded vignetting correction the render applies, so Fujifilm RAFs (and other makes with a lens database) are no longer brightened twice. The look version and the thumbnail cache version are bumped. Not yet measured on Chromaforge; upstream measured X-S10 mean dE00 2.71 to 2.55.
- **A camera profile and a look are two layers:** a camera profile with its own look develops "As profile" under the default look; any other look sits on its colour only, never stacked on the profile's look. The profile row names the camera profile under the look, the profile menu gains Camera Profiles, Settings ▸ Profiles lists and deletes imported camera profiles, and commands make, move and fill profile groups and set a body's own camera profile. Existing edits keep their look.
- **Sliders follow the first move:** a slider drag starts with the first point of travel, not after egui's click distance, so slow fine adjustments track the pointer. The drag is still one undo step.

## Library

- **More Metadata filter columns:** file format, ISO, focal length, aspect ratio, IPTC title / headline / caption /
  creator / copyright / location, develop preset and AI tools; the Unknown and Unrated rows can be picked (issue #777).
- **Natural-language (semantic) search:** turn on **AI** in the search bar (or the Modern search pill) to search the library with descriptive phrases using CLIP image-text embeddings (`clip-vit-b32-laion2b`, MIT, downloadable in Settings ▸ AI Models). Matches rank by similarity under the default sort, compose with ratings, flags, colour labels, keywords and folders, and update automatically as background indexing progresses (issue #487).
- **Square Grid is remembered:** choosing Square Grid in the Library is kept across restarts and detours through a photo — G, Esc, the filter bar and every other way back to a grid return to the style you chose last instead of Photo Grid. PR #815.
- **Arrows step through the selection:** with several photos selected, ← / → visit only those photos, in view order, wrapping at the ends, and keep the selection.
- **Grid thumbnails follow a drag on every selected photo:** with several photos selected, each one's thumbnail refreshes while a slider is dragged, not only the active photo's.
- **Memory for caches fits the computer:** the Settings choices go past 4 GB, up to the most the computer allows (`memory::max_budget`), and Automatic shows the size it picks.
- **No backup prompt for an unchanged catalog:** the quit backup prompt (and the backup on exit) is skipped when the catalog and its settings are the same as at the last backup.
- **Finishing an import survives a restart:** the photos and previews `library.finishImport` was asked for are kept in the library (`import-finishing.json`) until done; a library opened with an unfinished plan takes it up again. A finish the user stops is not resumed.

## Import

The import's windows, messages, undo step and file dialog (a filter for each catalog kind) name the program the catalog comes from. Fixes #844.
- **Import Settings fit long names:** the Import tab's settings column resizes by its left edge and remembers its width, the preset and camera profile lists are as wide as their longest name, Manage Presets… sits beside the preset stack, and the tab shows the Library toolbar, the filter bar and each photo's exposure. PR #840.
- **Browsed raws show their body's camera profile:** raws browsed in the Import tab (shown in place, not yet imported)
  render with their camera body's own camera profile, or the Import panel's choice for the body, exactly as importing
  them will apply it, with nothing written to the photo or its sidecar. A body profile set after the folder was
  browsed shows at once. Raws catalogued before serial numbers were kept are known by the serial their file states,
  and a renamed file's leading number (`10-…`) is no longer taken for a camera body. Thanks @OneSlips.

## Performance

- **Auto Mask strokes are kept and refined only where they reach:** each stroke's edge snap runs over the part of
  the photo it can touch, and finished strokes are kept between renders on the GPU and the CPU. On the GPU they
  are kept in blocks of the whole photo, so the tiles of the zoomed view share them. The GPU also works out one
  stroke at a time, so the window keeps drawing. Twelve big strokes at 100 % of a 45 MP photo: the zoomed view's
  tiles finish in 6.4 s instead of 15 s, and in 4.4 s instead of 15 s after going back from Fit. On the CPU, a
  render back from Fit takes 0.5 s instead of 11.7 s. Thanks @OneSlips. PR #825.
- **Brushing over a synced selection stays smooth:** while a brush stroke paints, and for a second after it, the other photos' thumbnails and the neighbour prefetch wait, so the photo being painted keeps the renderer to itself.

## Fixes

- **Lightroom import and collection-name rules:** a smart collection's Collection rule matches ordinary collections only, as in Lightroom Classic, so a rule matching a smart collection's name no longer makes the whole catalog import fail; a smart collection that would still include itself falls back to a plain collection on its own.
- **Nikon Z 6III colour:** remove an overfitted hue/saturation table from the camera's calibration that caused extreme purple and magenta discoloration across blue skies and shadows.
- Export with Remove location no longer copies an original HEIC, HEIF or AVIF whose metadata list is damaged or cannot be fully checked.
- **Lens profiles in cropped image areas:** raws from a full-frame Nikon shot in 5:4, 1:1, 16:9 or DX get the lens-database correction for their part of the sensor, placed by where the maker note says the frame sits. The full-frame profile used to be stretched over the smaller frame: on a Z 7 in 5:4 with a Z 50 mm f/1.8 S at f/1.8, 0.46 EV too much vignetting correction and 16 px of distortion error at the corners. 3:2 photos are unchanged.
- **Lightroom import, Copy Name and edit date:** a Copy Name on a photo that isn't a virtual copy is kept (without showing the photo as a copy), and each photo's edit date is its last edit in Lightroom Classic instead of the time of the import.
- **A plug-in's program wait asks before it stops:** the activity row of a plug-in waiting for a program names the program and the plug-in and says when the results come back; its ✕ is replaced by Stop Waiting…, which asks first, because stopping throws the run's results away while the program keeps running.
- **No empty grid for a deleted collection:** undoing a collection's creation, redoing its deletion or opening a library whose saved view names a deleted collection shows All Photos, and photos an undo took away are no longer acted on through the selection.
- **A keyword thousands of levels deep no longer takes gigabytes:** the keyword index kept a copy of nearly the whole keyword for every level of it; it now stops at the 128 levels the keyword tree keeps (one 100,000-level keyword took more than 20 GB of memory).
- **Small dialogs keep their size:** on wide screens dialogs such as Create Collection no longer stretch to the window's width.
- **One note per change:** P, X, U, undo and redo no longer show a toast as well as the on-screen overlay when the overlay reports every change.

## Improvements

- **HDR display on GNOME:** Wayland compositors that offer HDR only as BT.2100 PQ (GNOME's Mutter) now get an HDR window instead of SDR; `--hdr-probe` honours `<PREFIX>_HDR_DISPLAY=0` and says why a window stays SDR. Thanks @cromefire.
- **Import with a stack of presets:** the Import tab, the import review and its form list the develop presets an import applies, in order: add as many as you like, move one earlier or later, or take it off. Each preset sets its settings on top of the one before, as its own History step, and each raw keeps its camera body's profile through them unless "Presets may change the camera profile" is on. The stack and the camera profile chosen per body are kept for the next import, in the tab and the review alike. The single `preset` param of `library.import` still works, applied before `presets`. Thanks @OneSlips.
- **Country codes and keywords in metadata:** metadata presets save, import and export the ISO country code, offline reverse geocoding fills it, keywords are editable in the IPTC view, and the Location and Default views show Headline and Keywords (#784).
- **Breadcrumb "…" menu:** the folders a long path's breadcrumb hides are listed under its "…" and open with a click.
- **Culling marks under the thumbnails (Compact):** grid and filmstrip cells show flag, stars and label in a strip under the picture, a pick or reject glow behind it, and brighter selected and active cells.
- **Drives in Import:** the Import tab's sources list every drive and volume as a folder tree (This PC).
- **Resizable filmstrip:** its top edge drags it between 96 and 360 points (double click: back to 142); the height is remembered.
- **Shot info strip:** View ▸ Shot Info (Shift+I) shows aperture, shutter, ISO, focal length, lens and size under the loupe's photo.

## Fixed

- The Import tab no longer inherits the Library's filters: a card or folder is browsed with all of its files (the filter is restored when the Library tab returns).
- A module switch (the Modern layout's Develop switch, a shortcut, a command) while the Import tab is open first leaves the tab, instead of drawing another module's chrome over the stuck Import sheet.
- Video: MPEG-TS clips with interlaced (PAFF) H.264 group their two field access units into one frame sample again, so frame counts, seeking and Capture Frame work as before the FilmCraft access-unit change (issue #727).

## Added

- ISO country code metadata (`Meta::country_code`): edited via `photo.setMeta` (`countryCode`), shown in the Info panel's IPTC view and the Map module's side panel, filled by reverse geocoding from its place data, filterable as `countryCode`, and read from and written to XMP as `Iptc4xmpCore:CountryCode` (sidecars, imports and exports included).

## Map

- **Reveal the selection:** choosing a photo in the filmstrip while the Map module is up pans the map to its pin when the pin lies off screen (zoom unchanged, in-view pins never move the map), and double-clicking a thumbnail frames its pin and zooms in.
- **Location metadata on the map:** the Map panel shows the photos at the selected pin with the Metadata panel's editable fields — GPS, Sublocation, City, State / Province, Country, Title, Headline, Caption and Keywords — and an edit applies to every photo at the pin in one step.

## New features

- **Merge to Layers:** an HDR merge can also write a layered PSD/PSB of its frames, aligned exactly as the merge aligned them, with the merged result and the deghost map as optional layers. The file is stacked under the DNG (issue #769).

## Changed

- Video decoders and muxers pick up FilmCraft's latest upstream work: H.264/HEVC decode hardening (overlapping slices, absurd picture counts, overlapping macroblock slices), AV1 tile module split with cheaper dequantisation and a DC-only inverse DCT, AVI `idx1` recovery, MXF open-window and AES3 fixes, branch-free quantisation and byte-wise CABAC renormalisation in the H.264 encoder, and single-pass VBR/CBR overshoot payback.

## Features

- **Prepare photos in the background (Settings ▸ Performance):** the photos around the one in the loupe are made ready before you reach them, eye focus is found ahead, and the previews of every photo in view are built in the spare time, with separate settings for culling, the library and editing, a choice of which photos, and a library's own settings. The work waits for the photo on screen, pauses for exports and imports, skips photos whose previews are there, re-renders photos synced off screen, and is one cancellable row in the activity list. Commands `prefs.backgroundPrep` and `prefs.setBackgroundPrep`.
