# 26.46.2

## Develop and masking

- **Subject model only when needed:** with BiRefNet installed, Sky, Landscape and Depth masks (and folders of photos using them) no longer run "Finding the subject"; only masks that use the Subject selection do. Thanks @RalfKerkhoff for the report (#969).
- **Look-alike faces at once:** right-click an unnamed face in People to select its whole look-alike group to name or ignore, or to ignore that face alone (#259).
- **Face detection status:** Settings ▸ Faces loads the face detector and checks the GPU for it like recognition, instead of showing "Not loaded yet" (#978).

## Develop

- **Calibration Saturation fixed (process V9):** a primary's Saturation scales its distance from grey in linear light instead of its OkLab chroma, which bent blues in hue like the Hue slider. Edits on V1–V8 render as before. Issue #1031.
- **White Balance Selector readout:** the sampled colour's values show right under the selector's loupe. Issue #1094.
- **Brush overlay after a stroke:** a released brush stroke leaves the mask's overlay on show until a mask slider moves. Issue #1042.

## Library

- **Android: the camera roll watches for new photos.** Adding the camera roll (on the first-start question or later from Settings ▸ Folders) makes it a watched source: it is listed again when the app opens, comes to the front and every few minutes, and photos new to the library are imported in place without the review, so shots taken with the device appear on their own. A *Watch for new photos* checkbox on the camera roll's row in Settings ▸ Folders turns the watching off.
- Face detection (MediaPipe Face Landmarker: BlazeFace and FaceMesh) runs on the GPU through the face recognisers' wgpu kernels when a background check finds it matches the CPU and is faster; all of a photo's detector windows go to the GPU in one submission. Settings ▸ Faces shows the device; the CPU-only switch, lost-card fallback and activity row work as for recognition (#996).
- **Immich locked folders:** photos in Immich's locked folders can now be synced, imported and linked. The account card's Locked Folders section shows whether the app's server session is elevated, and Unlock… sends the account's PIN (4–6 digits, as `pinCode`) or password once (`immich.unlockSession`, never journaled); the unlock holds until Immich locks the session again. Sync no longer skips `locked` assets (they are simply absent from a locked session's listings). Issue #1023.
- **Validate DNG Files and Reset Export Status:** Library ▸ Validate DNG Files checks the selected DNGs' raw data against the checksum they carry, in the background, and lists the damaged and unverifiable files. DNGs the app writes now carry that checksum. Exported photos show a badge in the grid, and Photo ▸ Reset Export Status clears it. The catalog format is now 17 (older builds refuse a catalog opened by this one). Part of #983 and #984.
- Auto Import: option to include subfolders of the watched folder, plus file naming, develop preset, metadata preset and keywords for arriving photos (`library.autoImport` takes `subfolders`, `rename`, `preset`, `metadataPreset`, `keywords`). Subfolder listing idea from upstream #1117.
- **Culling suggestions (issue #489).** Assisted Culling suggests a 1–5 star rating and a Pick / Reject flag per photo from its focus, exposure and quality scores, and the dialog can apply them to photos you have not rated or flagged yourself (one undo step). The suggested stars are stored with the photo and filterable as a smart-collection rule field ("Suggested Stars"); `photo.analyze` reports every suggestion (`suggestedStars`, `suggestedFlag`) even without applying it. PR #1105.
- **Folders:** folders that only hold subfolders keep their rows, so the list nests as on disk; Show Parent Folder adds the parent to the Folders list (#1022).
- **Filmstrip:** resizing it keeps the active photo in place (#1082).

## Import, export and formats

- **HEIC/HEIF photos on Android:** the Android app now opens HEIC/HEIF photos (what iPhones shoot) with the same pure-Rust decoder as the desktop builds, so the import review, the camera roll and the file pickers accept them. Distributors who must avoid HEVC build the Android app with `--no-default-features`.
- **Email Photo:** File ▸ Email Photo… exports the selection as small JPEGs and opens a new message with them attached in the system mail program (`xdg-email`, Mail, Outlook). Without a mail program the files stay in a shown temporary folder.
- **Update DNG Preview & Metadata:** Metadata ▸ Update DNG Preview & Metadata appends a JPEG preview of the current edit and the current XMP to the selected DNGs, leaving the raw data byte for byte as it was; Adobe-written and unrecognised DNGs are refused.

## Import

- **Lightroom catalog import: saved prints** become Saved Prints instead of plain collections: page size and margins, Single Image / Contact Sheet grids, Picture Packages and Custom Packages with each cell's position and photo, image settings (Zoom to Fill, Rotate to Fit, stroke), page options and the Print Job (destination, resolution, sharpening, media, intent, Print Adjustment, 16-bit). Reimporting a catalog upgrades its earlier plain albums once; the report counts `savedPrints` and lists what didn't carry over.

## Interface

- **Presets no longer replace the Edit panels:** Develop's presets could open as a column on the right in place of Edit (after importing presets with the left column hidden, or from Window > Panels > Presets), leaving no adjustments on screen. They are now only ever the Presets panel of the left column, which the command and a preset import bring into view.
- **Right-panel button could do nothing:** the top bar's right-panel button and F8 used a different switch from Tab and Window > Panels, so after Tab hid the side panels the button only toggled a hidden state. Both now act on the same side, in every module that has a right column of panels.
- **Before/After not saved:** Show Before (`\`) and the Original Photo box are momentary view modes again — quitting with one on no longer reopens with the loupe frozen on the original while the Navigator shows the edits (#1110). PR #1117.

## Performance

- **Large libraries open much faster from network shares and hard disks:** the catalog store is read front to back in one pass and opened from memory, instead of one 4 KiB page at a time in key order (a round trip or a seek each: nearly 8 minutes for 328,000 photos in #979). Stores over 4 GiB, or that don't fit in memory, are read as before. Thanks @GregDunn1953 and @1234destiny1234 for the logs. PR #1026.
- **Culling stays responsive while photos are prepared in the background:** the background build made every photo's render jobs on the interface thread when it started and at every folder change (1.2-1.5 s frozen each time); its jobs are now made a few photos a frame, nearest the user first, and the preparation renders on its own lowest-priority thread pools. The loupe waits up to 1 s for a preview the build is already making instead of decoding the same raw twice (its look-ahead skips the photo being built), its first picture of a raw is the small camera JPEG before the full-size render (slowest first picture 1,338 ms to 384 ms), and holding a step key makes thumbnails 30 photos ahead instead of 5. Thanks @OneSlips. PR #1051.
- **Masks over the storage-buffer limit stay on the GPU:** a 45 MP export with 12 radial masks and a Subject mask needed one 2,220 MiB buffer for the mask planes, over the 2,047 MiB storage-buffer limit, and fell back to the CPU (about 10 s per photo instead of about 1.6 s). Masks that don't fit together now each get their own buffer and the per-pixel finish pass reads them band by band, so heavily-masked exports stay on the GPU and take about 2.5 s instead of about 10 s. Thanks @OneSlips. PR #1054.
- **Confirming a hot pixel rebuilds one camera's previews:** preview, thumbnail and view cache keys carried one generation number for the whole process, so confirming one hot pixel made every preview in the library miss; the keys now carry a number for the corrections that apply to the photo's own camera body, so only that body's previews are rebuilt and previews already on disk stay valid (a small baseline file beside the body maps remembers the corrections in use at the switch). Thanks @OneSlips. PR #1078.
- **No more Vulkan driver stalls at 100 % zoom:** every GPU render created new upload and readback staging buffers, and NVIDIA's Vulkan driver holds a process-wide lock for 80-250 ms on each allocation or free, so drags at 100 % stuttered on Vulkan (22-28 frames over 100 ms in 9 drags) but not on DX12. Staging buffers are now reused from pools, each card's pool may hold up to a third of its own memory while it works (the idle trim still empties it), and every failure path falls back to the old behaviour: nine drags at 100 % stay under 100 ms after the first (worst 36 ms, was 576 ms). Thanks @OneSlips. PR #1062.
- **Faster editing on photos with AI masks:** dragging a slider no longer evaluates every mask again — the mask caches compare the photo's mattes by content instead of by pointer, so a drag hits the cache — and the Subject and scene model analyses are keyed by the photo's identity instead of its decoded pixels, so they run once per photo, whatever size it is decoded at, shared between the loupe, a 1:1 window and exports (the Subject model takes 11–23 s on the processor, up to 160 s under load, and one photo ran it three times while being edited). A Source plug-in filter, or a source without identity, keeps the old pixel key. Thanks @OneSlips. PR #1052.
- **No UI stalls while exports or Build Previews run:** the Windows build embeds an application manifest that opts the executable into the Segment Heap (Windows 10 2004 and later; older versions ignore it) — on the default NT heap every large free took one process-wide lock, and while batch work ran, the render workers' image buffers kept it busy: the window's thread waited on it in ~45 % of samples, with frames of 50–300 ms. Thanks @OneSlips. PR #1052.
- **GPU memory is freed after batch work:** the idle trim frees both graphics cards' buffer pools (the second card's kept up to an eighth of its budget for the rest of the session), and the renderer trims again once batch work has finished, if the pools grew since its last trim. Measured after an export of 50 photos and a 1:1 build of 60: 3.8–4.0 GB of buffers still pooled after 30 s idle, now freed. Thanks @OneSlips. PR #1052.

## Fixes

- **Flat-Field Correction follows a steep fall-off:** the gain maps are measured on a lattice of about one point every 86 pixels that reaches the frame's edges (a plane fit around each point, mildly smoothed) instead of a degree-4 surface through 17 × 17 points, which left the corners of wide lenses wide open 0.2 to 0.7 EV too dark (and up to 0.16 EV even at 105 mm). Gains may now reach 4 EV.
- **Memory (Linux):** freed allocator pages (`malloc_trim`) are returned to the system after a background preview build, so the resident size no longer stays near its peak (upstream #4054).
- **A failed Lightroom import takes back the photos it added.** The records made for the catalog's originals are removed when the import then fails, rather than staying behind with only the error reported (upstream #4087).
- **Lightroom import: records that name no photo are left out.** A develop settings, metadata, keyword, history, snapshot or album-member record whose `image` is missing, NULL, text or a fraction no longer goes to photo 0 (or 2.5 to photo 2); each table reports one warning (upstream #4090).
- A Lightroom import with a refused photo whose id is 0 (a malformed catalog) refuses only that photo and no longer skips every master (upstream #4072).
- **Cancelling a large AI batch froze the app for a moment:** stopping tens of thousands of waiting AI jobs (the ✕ on the AI activity row, or Cancel all) wrote one log line per job while the UI waited, 48,946 lines and a half-second freeze in one report (#979). It now writes one line.
- **No crash when the GPU device runs out of memory or is lost:** egui-wgpu panicked when the window's device gave no staging buffer for a frame's index/vertex data, and wgpu's `create_buffer_init` panicked on the invalid buffer in GPU renders, face/CLIP/denoise jobs. The window now logs and skips the frame, and every GPU buffer upload goes through `Queue::write_buffer`, which reports the failure as a device error so the render falls back to the CPU; clippy now bans `create_buffer_init`. Seen on a Qualcomm Adreno X1-45 (Vulkan, Windows on ARM) while scrolling a 49k-photo library. Issue #1029, thanks @pokemonbattledroid.
- **Develop stops freezing at 100 % zoom and beyond:** returning to 100 % keeps the photo on screen's rendered tiles instead of re-rendering every tile from the original (about 5 s for a 45 MP raw, now about 150 ms), the window's interactive renders are measured separately and go ahead of export and 1:1-preview renders instead of waiting behind them, 1:1 tiles render on the second graphics card when one is present, and big look-ahead pictures upload at most one per frame. The histogram's clipping triangles now start their hover preview once the pointer rests about 0.3 s on one, instead of at every crossing. Thanks @OneSlips. PR #1063.
- **Background preparation stuck on "Stopping…":** a photo on screen that the build leaves out of its view (unmarked with "Picks, rated and labelled", or hidden by the filter) stopped the build as if the user had moved on, and the same build was started and stopped again every frame, so the loupe and the filmstrip never rendered (regression in 26.46.1).
- **Background preparation:** a build of the previews that did not run to its end is owed to the library (`prepUnfinished` in its preferences) and is taken up again for the view shown once it has been still for 3 seconds, from the grid and after a restart; switching previews off and on again no longer counts as the user stopping the build, and a build left running by the library before is stopped when another library opens (upstream #4093, issue #3947).
- **macOS: the Import screen clears the traffic lights** (#1083): its ‹ back button and title start right of the window buttons, as Settings' do.
- **Check for Updates over the welcome dialog** (#929): the update dialog is no longer drawn under the welcome card; the card returns when it closes.
- **Develop: Edit title on the button row** (#530): the title shares a row with Auto, B&W and HDR.
- **Delete, X and the tool keys act only on a tool that is on screen.** A saved Masking, Remove, Red Eye or Crop panel no longer takes Delete or X (or H, A, O) in the grids, Compare, Survey or the full-screen preview (upstream #4132).
- **Exports can't reach an original through `..`.** A destination whose `..` runs through a folder that doesn't exist yet is refused instead of being checked as a free name (upstream #4125; the rest of that PR was already taken from #2634).
- **Lightroom import: a collection member whose `collection` is not an id joins no album.** It no longer lands in collection 0 or the truncated id; the import reports one warning (upstream #4098, issue #4095).
- **Lightroom import: an image with a broken file reference is skipped.** An image whose `rootFile`, `folder` or `rootFolder` reference is missing, NULL, text or a fraction no longer resolves to record 0 (or 1 for 1.5) and merges into another photo; it is skipped with the existing missing-file/folder/root reasons (upstream #4097, issue #4094).

## Camera colour

- Calibrations can be keyed on the lens model (#1015): a lens-specific calibration is used only for photos taken with that lens, a lens-less one for every other photo of the camera, and another lens's calibration never. `calibrate-lightroom fit`/`add` take `--lens`, and `add` refuses to overwrite a calibration for the same camera, lens and editor without `--replace`.

## Features

- **Advanced Search (issue #846):** a dedicated panel (Library > Advanced Search…, Ctrl/Cmd+Shift+F) with granular structured field filtering — global word matching, file/collection/keywords, item properties (dimensions, rating, color label, aspect), caption/title, photograph information (camera, lens, focal length, ISO, shutter speed, aperture), location, audio/video duration, and faces — whose results the grid shows as a filtered view. Codec and frame-rate filtering are declared but not supported yet. Enter Full Screen moves from Cmd/Ctrl+Shift+F to F11 (and the macOS system key Cmd+Ctrl+F).
- **Library > Review Comments:** shows the comments on the photos published to an Immich service (the album's activity: author, date, text), per photo, with Refresh; `publish.reviewComments` returns them for the control channel and MCP. Immich publish services now report comments as supported; Hard Drive and SFTP say they have none.
- **Library ▸ Find Duplicates…:** groups photos that are copies of one another across the whole library. Same-file copies are found at once from the catalog's content hashes; Find Similar Copies reads every photo's picture in the background (a raw by its camera JPEG, a clip by a poster frame) and finds copies that differ (resized, re-compressed, renamed) plus raw + JPEG pairs of the same shot, kept apart as something to stack rather than delete. The best copy of each group comes first and unmarked, the rest marked; Remove sends them to Recently Deleted, Reject flags them, Stack Groups stacks each group. `library.findDuplicates {similar}` returns the groups for the control channel and MCP.
