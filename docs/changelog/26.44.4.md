# 26.44.4

## Interface

- **Plug-in Manager rework:** one window with the list on the left (Plug-ins and Pixel Filters, each entry with an icon drawn from its id and an enabled, disabled or didn't-load mark) and the selected entry's page on the right: Settings, Permissions, About and Log tabs for a plug-in (the Settings tab replaces the separate settings window and keeps the values typed when a save fails); stage, measuring, base tone, parameters, module size and hash for a pixel filter; the error and Remove for a module that didn't load, listed in its kind's section. *Install from File…* opens the file picker instead of a path box, a `.wasm` dropped on the app while the window is open installs it, and the footer names the plug-ins folder with *Show Folder* (`plugins.showFolder`). Cmd+Alt+Shift+, opens the window in both keymap sets. `plugin.list` gives a filter's module `size` and each failed row's `kind`; `plugin.enable` on a filter says filters can't be turned off.
- **Rotate and flip in Crop & Straighten:** the Crop & Straighten panel gains rotate and flip controls (issue #705).

## Library

- **"No stars" filters show the unrated photos:** filtering by "= no stars" or "≤ no stars" now shows the unrated photos instead of turning the filter off and showing every photo; the chip reads "Unrated", and Rating ▸ None clears it. A smart album saved with an exact or at-most rating of 0 now shows only unrated photos.
- **Auto Import reports a folder it can't read:** Settings ▸ Import says "Can't read this folder: …" instead of failing silently, and Auto Import waits for an import that starts while it is listing the folder.
- **Settling waits for the Missing Photos count:** the count is part of the library finishing its load, and a thread the system refuses to start no longer panics (the last count is kept and retried).

## Import, export and formats

- **Canon CR2 opens with the camera's aspect crop:** as a CR3 already did. CR2 photos shot at a non-sensor aspect now open at that crop; a crop or local adjustment made on one before may sit slightly differently on the new frame.
- **Export sizes keep the pixels you type:** a width or height of 1080 stays 1080 instead of snapping to 1088.
- **Sidecar crops without HasCrop import:** a sidecar or catalog that stores crop fields without the HasCrop flag now brings its crop in, as the catalog import already did. Presets still need HasCrop, so a preset can't change a photo's crop by accident.

## From upstream

- **Fixes ported from the weekly upstream review:** a Samsung encryption key past the 64-bit limit, byte counts near the 64-bit limit in ORF, SRW, ARW and PEF raws, a mask id at the 32-bit limit, and more than 64 red-eye corrections on a photo can no longer overflow or exhaust a render; the control channel refuses gesture numbers past any screen instead of queueing NaN positions; lens-database XML with mismatched closing tags is rejected (a third-party lens file that has them is skipped with a log line instead of loading leniently); a SAM 3 checkpoint in the original (non-Hugging Face) format says so.

## Fixes

- **Quitting while the GPU starts no longer disables it:** quitting during GPU device creation used to leave the crash marker behind, so the next launch said the app had closed unexpectedly and turned GPU rendering off.
- **The GPU adapter setting reaches photo rendering:** the GPU adapter environment variable now chooses the graphics card for photo rendering, not only for AI. A name that matches no card falls back to the default card with a warning instead of turning the AI device off.
- **Panic log in the settings folder:** a crash writes its log beside the other logs instead of the system temp folder; with preferences disabled it goes to the console only.
- **Flatpak can reach the accessibility bus:** a screen reader such as Orca can read the app inside the Flatpak sandbox (not yet tried on a real Linux desktop).
